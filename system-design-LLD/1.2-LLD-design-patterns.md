# Low Level Design

Low-Level Design (LLD) or Object-Oriented Design (OOD), is the process of defining the actual code structure, class hierarchies, and internal logic for individual software components

# Design Patterns

In Low-Level Design (LLD), design patterns are reusable blueprints for solving common, recurring problems in software design.

## 1. Creational

Creational controls object creation.

1. **Singleton**: for global system orchestrators, loggers, or database connection managers.
2. **Builder**: for creating complex data objects (like a `UserAccount` or an `Invoice`) with 10+ optional parameters without making an unreadable, messy constructor.
3. **Factory**: for a family of related products (like types of vehicles, types of hotel rooms, or types of notifications) and need to create them dynamically.
4. Abstract factory
5. Object pool
6. Prototype

## 2. Structural

Structural patterns focuses on how different classes/objects are arranged together so that larger problem can be solved in flexible way.

1. **Adapter**: for interacting with an external, third-party API or legacy system (like integrating Stripe or PayPal).
2. **Decorator**: for dynamically stacking or add extra features/fees onto a base object.
3. Proxy
4. Facade
5. Composite
6. Bridge
7. Flyweight

## 3. Behavorial

Behavorial focuses on how different objects communicate or interact with each other.
Structural Pattern create skeleton, but how skeleton coordinates, interacts is guided by Behavorial patterns.

1. **Strategy**: for different business rules, algorithms, or payment methods.
2. **Observer**: for asynchronous communication, pub-sub systems, real-time dashboards, and notification engines.
3. State
4. Chain of Responsibility
5. Template
6. Iterator
7. Interpretor
8. Command
9. Visitor
10. Meditator
11. Memento
12. Null object

# Relationships

1. **is-a** relationship is inheritance
   Eg. A two wheeler is a vehicle
2. **has-a** shows links between two objects
   e.g. House has rooms, Employee has a manager

## Association

General term for has-a relationship

1. Weak relationship (Aggregation)
   Existence of one object is not dependent on another
   E.g. Library has books
2. Strong relationship (Composition)
   Existence of one object is dependent on another
   E.g. House has rooms
